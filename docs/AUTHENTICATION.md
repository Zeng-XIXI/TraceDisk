# TraceDisk 离线许可证机制

## 工作流程

1. TraceDisk 在 macOS 读取 `IOPlatformUUID`，在 Windows 读取系统 `MachineGuid`，加入产品域后计算 SHA-256；界面只显示 64 位哈希，不暴露原始系统标识。
2. 客户把机器码交给软件提供方。提供方在 Java/Vue 授权中心选择期限，用 Ed25519 私钥签发许可证。
3. 客户把 119 位许可证粘贴回 TraceDisk。Rust 使用构建时嵌入的公钥离线验证签名、机器标记、签发时间和到期时间。
4. 验证成功后许可证保存在应用配置目录，下次启动自动复验。有效状态只保存在进程内；所有磁盘命令仍会在 Rust 层检查状态。

## 构建

先从授权服务的密钥生成器取得公钥，然后在每次开发或发布构建时传入同一个值：

```bash
cd apps/desktop
TRACEDISK_LICENSE_PUBLIC_KEY='Base64公钥' npm run tauri dev
TRACEDISK_LICENSE_PUBLIC_KEY='Base64公钥' npm run release -- 0.1.1
```

Release 构建若没有设置公钥会直接失败，避免意外发布一个无法激活的安装包。私钥绝不能进入 TraceDisk 源码、构建环境产物或客户电脑。

## 格式与边界

- 固定负载：版本 1 字节、机器标记 16 字节、签发时间 4 字节、到期时间 4 字节。
- 签名：Ed25519 64 字节，签名输入包含 `TraceDisk-License-v1` 产品域。
- 编码：完整 89 字节采用无填充 Base64URL，结果固定 119 个字符。
- 无数据库，因此许可证无法单独提前吊销。更换并重新构建公钥会使旧许可证整体失效。
- 到期判断使用离线电脑的系统时钟。系统时间被回拨时无法仅靠纯离线软件可靠发现；需要更强控制时应加入周期性在线校时或可信硬件时钟。
