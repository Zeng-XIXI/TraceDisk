# TraceDisk 启动验证机制

## 当前版本

- 每次启动 TraceDisk 都会进入独立验证页面。
- 当前临时验证码为 `123456`，只在 Rust 后端保存和比较。
- 验证成功状态只保存在当前进程内，退出或重启后失效。
- 未验证时，磁盘识别、镜像检查、扫描、停止扫描、容量检查和恢复命令都会被 Rust 后端拒绝。
- 输入错误验证码时，后端清除验证状态并关闭应用，不会开始读取磁盘。

这个本地固定验证码只适合开发和内部预览，不能作为正式授权方案。桌面程序可以被逆向分析，因此不能把固定密码本身视为不可提取的秘密。

## 后续 Java 验证服务

前端继续调用同一个 `verify_access_code` Tauri 命令。只需要把 Rust `auth.rs` 中的本地比较替换为 HTTPS 请求，不需要修改验证页面或其他磁盘命令。

建议 Java 服务提供类似接口：

```text
POST /api/v1/access-codes/verify
Content-Type: application/json

{
  "code": "用户输入的验证码",
  "clientNonce": "本次随机值",
  "appVersion": "0.1.0"
}
```

成功响应至少包含：

```json
{
  "valid": true,
  "expiresAt": "2026-08-05T12:00:30Z",
  "serverTime": "2026-08-05T11:59:45Z"
}
```

服务端应以自己的时间判断验证码是否处于一分钟有效期内，并将验证码设置为一次性使用；客户端不能只依赖本机时钟。接口应启用 HTTPS、请求频率限制、失败次数限制和验证码哈希存储，日志中不能记录完整验证码。
